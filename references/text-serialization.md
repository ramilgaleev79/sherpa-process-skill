# Сериализация значений переменных в .process (подтверждено golden)

Источник истины: `golden/manifest.yaml` (серия real/). Всё ниже — побайтово подтверждённые факты, не гипотезы.

## Скаляры в DiagramProperty (декларация)

| Тип | Хранение @DefaultValue/@Value | Пример |
|-----|-------------------------------|--------|
| Number | плоская строка | `0` |
| Logical | `True` / `False` | `False` |
| Text | бинарный контейнер → Base64 | см. ниже |
| DateTime | плоская строка `dd.MM.yyyy HH:mm:ss` | `05.06.2023 18:48:20` |
| Object / Money | пустая строка (значение задаётся блоками) | `` |
| SecureString (пустой) | пустая строка | `` |

Проверено по текущему корпусу `.process` (replay: 208 файлов): непустые значения
`Type=Text` **всегда** в контейнере (126/126), `Number`/`Logical`/`DateTime`/`Object` —
всегда плоской строкой. Ранее на 211 файлах было 260/260.

В рантайм-выражениях Logical = `$True`/`$False` — формы различаются.

## Text-контейнер

```
Base64( PREFIX + encode_7bit(len(UTF8(ps_literal))) + UTF8(ps_literal) + 0x0B )

PREFIX (22 байта, константа на всех образцах):
  00 01 00 00 00 FF FF FF FF 01 00 00 00 00 00 00 00 06 01 00 00 00
```

Примеры (проверено golden, серия b05-text-variants):

| IR-строка (значение) | PS-литерал | Байты после PREFIX |
|----------------------|-----------|--------------------|
| `` (пусто) | `""` | `02 22 22 0B` |
| `Test123` | `"Test123"` | `08 …` + `0B` |
| `Привет мир` | `"Привет мир"` | `15` (21 байт UTF-8) + `0B` |
| `Он сказал "Тест"` | `"Он сказал \`"Тест\`""` | b05 TextQuotes |
| `"Он сказал ⏎ "Тест"` (с LF и кавычками по краям) | `""Он сказал \`n\`"Тест\`"""` | b05 TextMultiline |

Base64 пустой строки целиком: `AAEAAAD/////AQAAAAAAAAAGAQAAAAIiIgs=`.

Правила экранирования (подтверждены b05): кавычка внутри — `` `" ``; перевод строки — `` `n ``; кавычка в начале значения после открывающей — удвоение `""` (комбинированный случай TextMultiline — разобрать детально в фазе 3 перед реализацией writer'а).

7-bit длина — длина UTF-8-байтов литерала, little-endian по 7 бит (для < 128 — один байт).

PS-литерал — обычный синтаксис PowerShell: двойные кавычки, backtick-экранирование (`\`n``, `\\\````).

## Общий заголовок бинарных контейнеров

Первые 17 байт одинаковы у Text/Hashtable/Dictionary/DataTable:

```
00 01 00 00 00 FF FF FF FF 01 00 00 00 00 00 00 00
```

Далее `06`, затем формат расходится: Text → `01 00 00 00` + строка; коллекции/DataTable → `02 00 00 00` + .NET-типы с AssemblyName (`System.Data…`, `System.Collections…`). Похоже на BinaryFormatter-подобную сериализацию Sherpa; точная раскладка коллекций — фаза 3, образцы в `diag07` (Hashtable/Dictionary) и `diag11`/`main-rich` (DataTable).

## Правила для генератора

1. Экранирование XML (Base64-строка безопасна) выполняется на последнем шаге сериализации; в IR — чистые строки.
2. Длина = длина UTF-8-байтов, не символов (кириллица: 1 символ = 2 байта).
3. PREFIX не выдумывать: это константа из golden; при смене версии Designer — переснять.
4. **Payload бывает двух видов** (проверено на 260 значениях): PS-литерал `"…"` — 252 случая,
   «сырые» байты без кавычек — 4 случая (путь `C:\…\file1.txt`, `A`, GUID-подобный токен,
   пустая строка). Генератор всегда пишет PS-литерал; читатель использует
   `text.decode_lenient()` для чужих файлов и строгий `text.decode()` для своих.
5. **Переводы строк в XML-атрибутах** — только сущностями: CR → `&#xD;`, LF → `&#xA;`
   (`compiler.xml_attr_escape`). Иначе XML-нормализация атрибутов заменяет их пробелами;
   ошибка ловится replay-тестом на многострочном `DisplayName` (`Comment`, 544/547 байт).
   При этом контейнер Text хранит уже готовый PS-литерал, где LF записан как `` `n ``.
